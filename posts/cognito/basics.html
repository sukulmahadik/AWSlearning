Start here: the basic ideas in plain words

This document assumes no prior knowledge of login systems. Read this section first; every later section builds on these eight ideas.

1. Authentication vs authorization

  • Authentication means proving who you are. Typing a password, using Face ID, or clicking "Sign in with Google" are all authentication.
  • Authorization means deciding what you are allowed to do once we know who you are. Can you read this file? Delete that record?
  • Everyday example: at an airport, showing your passport is authentication. Your boarding pass deciding which plane and seat you get is authorization.

2. Identity provider (IdP)

An identity provider is any service that keeps user accounts and can vouch for them. Google, Microsoft (Entra ID), Okta, Facebook and Apple are identity providers. When a website lets you "Sign in with Google", Google is the IdP: it checks your password and then tells the website "yes, this is really Maya".

3. Federation

Federation means one system agrees to accept another system's word about who a user is. If your app federates with Google, your app does not store passwords at all; it trusts Google's confirmation instead.

4. Token

A token is a digital pass handed to you after you log in. Instead of sending your password with every request, your app sends the token. Like a wristband at a concert, it is quick to check, says who you are and what you may do, and expires after a while.

5. JWT (JSON Web Token)

A JWT, pronounced "jot", is the most common token format. It is a long string with three parts separated by dots:

  • a header, saying how it was signed
  • a payload, holding facts about the user (these facts are called claims)
  • a signature, a tamper-proof seal from whoever issued it

Anyone can read the payload, but nobody can change it without breaking the signature. That is how an API can trust a token without calling the issuer every time.

6. OAuth 2.0 and OpenID Connect (OIDC)

  • OAuth 2.0 is a standard set of rules for letting an app get a token to access something on a user's behalf, without the app ever seeing the user's password. It is about authorization.
  • OIDC is a thin layer on top of OAuth 2.0 that adds authentication: it defines an ID token that says who the user is.
  • Cognito, Google, Okta and almost every modern login system speak both.

7. Scopes and claims

  • A claim is a single fact inside a token, such as email: maya@example.com or groups: admin.
  • A scope is a named permission the app asked for and was granted, such as orders/read. Scopes appear inside the token as one of its claims.

8. IAM role and STS

  • In AWS, IAM (Identity and Access Management) decides who can do what to which AWS resource.
  • An IAM role is a named set of permissions, for example "may read files in this S3 bucket". Nobody owns a role permanently; you borrow it for a while.
  • STS (Security Token Service) is the AWS service that lends you a role: it hands out temporary credentials (a short-lived key) that carry that role's permissions, usually for about an hour.

The big picture

Amazon Cognito is AWS's service for handling user logins so you don't have to build them yourself. It has two main parts that do different jobs: a User Pool checks who the user is, and an Identity Pool gives that user temporary permission to use AWS services.

An office building analogy

Imagine visiting a large office building:

  1. You arrive at the front desk. They check your ID (or phone your employer to confirm you work there) and print you a visitor badge with your name and department. → This is the User Pool. The badge is a token.
  2. Your employer vouching for you over the phone is like Google or your company's login confirming who you are. → These are identity providers.
  3. The front desk only deals with approved companies, and each company has a registered account number with the building. → That account number is a client ID; it identifies which app is asking.
  4. To open doors, you take your badge to the key-card office, which gives you a key card that opens certain floors and expires tonight. → This is the Identity Pool. The key card is a set of temporary AWS credentials, and the list of doors it opens is an IAM role.

Who does what

Piece Plain-English job What it hands out
Identity provider (Google, Okta, the User Pool itself) Checks the password and confirms who the user is Proof of identity
User Pool Keeps your app's list of users and runs the login Tokens (ID, access, refresh)
App client (client ID and secret) Identifies which application is asking Cognito for a login Nothing; it is a registration
Identity Pool Swaps a token for temporary AWS access Temporary AWS credentials
IAM role The list of AWS actions those credentials allow Permissions
