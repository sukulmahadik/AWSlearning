Amazon Bedrock AgentCore Identity does not replace Cognito. Cognito (or another identity provider such as Okta or Entra ID) still logs in the person; AgentCore Identity manages identity around an AI agent: who may call the agent, who the agent itself is, and which outside services it may use on a person's behalf (AWS docs).

The three questions in an agent system

Question Who answers it How
Who is allowed to call this agent? (inbound) Cognito issues the token; AgentCore Identity checks it at the agent's door You point AgentCore at the User Pool, and it verifies tokens just like your API would
Who is the agent itself? AgentCore Identity Each agent gets its own workload identity, so actions can be traced to "this agent, acting for this user"
What outside services may the agent use for the user? (outbound) AgentCore Identity A token vault stores each user's tokens or API keys for services like Google Drive or Slack; if consent is missing, it runs the approval flow (see the callback section)

How it all connects

  1. The user signs in through Cognito (perhaps via Google) and the app receives a Cognito token.
  2. The app calls the agent with that token; AgentCore Identity checks it.
  3. The agent needs the user's Google Drive, so it asks AgentCore Identity for a Drive token for this user.
  4. AgentCore returns a stored token, or sends the user to approve access first.
  5. The agent calls Google Drive.

For a machine caller, such as another service invoking an agent gateway, the same User Pool can issue a client credentials token, exactly as in "One User Pool, two kinds of callers".
