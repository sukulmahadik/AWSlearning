Pricing and limits

AgentCore Identity is free when you use it through AgentCore Runtime or AgentCore Gateway. Used any other way, for example from an agent you host on ECS or Lambda, it costs $0.010 per 1,000 tokens or API keys requested by the agent for non-AWS resources (AWS pricing, as of October 2026).

What else you pay for

  • The services around it: AgentCore Runtime and Gateway have their own pricing, and so does the identity provider (for example Cognito monthly active users, or machine-to-machine token requests).
  • AWS Secrets Manager for stored client secrets and API keys, and AWS KMS if you use a customer-managed key.
  • The outside services themselves, under their own terms.

Limits worth knowing

  • Authorization URLs and their session IDs expire after 10 minutes; the user must approve within that window.
  • Each runtime uses one inbound method: IAM or JWT, not both.
  • Service quotas apply to the number of workload identities, credential providers and request rates. Check the AgentCore quotas page in the AWS documentation before designing for very large numbers of agents or providers.
  • Prices, regions and quotas change; confirm on the AWS pages before relying on them.

How AgentCore Identity relates to Cognito

They work together rather than compete. Cognito (or another identity provider) signs in the people. AgentCore Identity manages identity around the agent: who may call it, the agent's own identity, and the credentials it uses for each user.

Question Cognito User Pool AgentCore Identity
Stores users and passwords? Yes No
Signs users in, with MFA and "Sign in with Google"? Yes No
Issues login tokens (JWTs)? Yes No; it checks them on the way in
Gives the agent its own identity? No Yes, a workload identity
Stores per-user tokens for Google, Slack, GitHub? No Yes, in the token vault
Runs consent flows to outside services for an agent? No Yes
Issues AWS credentials? No (an Identity Pool does) No (agents use their IAM role for AWS)

How they fit in one system

  1. Maya signs in to your app through a Cognito User Pool, perhaps using "Sign in with Google".
  2. Your app calls the agent with Maya's Cognito token.
  3. AgentCore Identity's inbound authorizer checks that token against the pool's discovery URL and your app client ID.
  4. The runtime creates a workload access token for the agent acting for Maya.
  5. The agent asks AgentCore Identity for Maya's Google Calendar token; the token vault returns it or runs the consent flow.

Two separate Google registrations. If users sign in with Google and the agent reads their Google data, you register two OAuth clients at Google: one for Cognito (redirect to Cognito's /oauth2/idpresponse, scopes openid email profile) to sign users in, and one for AgentCore Identity (redirect to AgentCore's callbackUrl, scopes such as calendar.readonly) to reach their data. Signing in with Google does not give the agent a usable Google API token.

Cognito in other roles. Cognito can also be an outbound provider (the CognitoOauth2 vendor) when the agent calls an API protected by a different User Pool, typically with machine-to-machine client credentials and custom scopes.

For a full explanation of User Pools, Identity Pools, client IDs, PKCE and tokens, see the companion guide, Cognito, Explained.
