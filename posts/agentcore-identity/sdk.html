The AgentCore Python SDK (bedrock-agentcore) gives you two decorators that turn credential handling into one line above a function: @requires_access_token for OAuth tokens and @requires_api_key for API keys. The decorator fetches the credential before your function runs and passes it in as an argument.

@requires_access_token

import asyncio
from bedrock_agentcore.identity.auth import requires_access_token

@requires_access_token(
    provider_name="google-provider",                       # the credential provider's name
    scopes=["https://www.googleapis.com/auth/calendar.readonly"],
    auth_flow="USER_FEDERATION",                           # 3LO: act for the signed-in user
    on_auth_url=lambda url: send_to_user(url),             # what to do if consent is needed
    force_authentication=False,                            # reuse the stored token if there is one
)
async def list_meetings(*, access_token: str) -> list:
    # access_token is a Google token for this agent and this user
    ...

meetings = asyncio.run(list_meetings())

The parameters

Parameter Required What it does
provider_name Yes Which credential provider to use
scopes Yes The OAuth scopes to request; an empty list for many M2M providers
auth_flow Yes "USER_FEDERATION" (3LO), "M2M" (2LO) or "ON_BEHALF_OF_TOKEN_EXCHANGE"
on_auth_url For 3LO A function that receives the authorization URL when the user must approve; send it to your app, chat UI or console
callback_url For 3LO Your app's return URL for session binding; if omitted, the runtime's configured one is used
force_authentication No, default False True clears the stored token and forces a fresh consent; use it when a token was revoked
custom_state No An unguessable value echoed back through the flow, for extra request checking
custom_parameters No Extra parameters some providers need on the authorization request
into No, default "access_token" The name of the argument the token is passed in as

What happens when the function is called

  • First time for this user (3LO): the decorator calls on_auth_url with a consent link and waits while the user approves. Then it fetches the token and runs your function.
  • Later calls: it returns the stored token from the vault, or refreshes it silently if it expired and a refresh token exists.
  • If the refresh token has also expired: the user is asked to approve again.
  • M2M: no user step; it fetches or reuses the agent's own token.

Getting the consent link to the user. Printing the URL works only on your laptop. In a real app, stream it back to the caller as part of the agent's response, for example:

on_auth_url=lambda url: stream_to_caller({
    "type": "authorization_required",
    "authorization_url": url,
    "message": "Please connect your Google Calendar to continue",
})

Your app then shows a "Connect Google" button. Many agent frameworks surface this as a tool result that asks the user to authorize.

@requires_api_key

from bedrock_agentcore.identity.auth import requires_api_key

@requires_api_key(provider_name="weather-api-key")
async def get_forecast(city: str, *, api_key: str) -> dict:
    ...

It takes provider_name and an optional into (default "api_key").

Using them as agent tools

The decorators wrap ordinary functions, so they work inside any agent framework. A common pattern with Strands Agents is to decorate the helper that calls the outside API, and call it from the tool the model sees:

from strands import Agent, tool

@tool
async def upcoming_meetings() -> str:
    """List the user's meetings for the next 7 days."""
    meetings = await list_meetings()       # decorated helper from above
    return format_meetings(meetings)

agent = Agent(tools=[upcoming_meetings])

These examples follow the documented decorator signatures but have not been run here; adapt names, scopes and helpers such as send_to_user to your app.
